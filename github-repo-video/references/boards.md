# 画面规范（一屏一块）

配合 `scripts/video_boards.py`（画面定义）与 `scripts/board_css.py`（局部样式）使用。
核心原则：**为每一句口播单独设计一屏**，映射关系不复存在，也就无从错位。

---

## 一、画幅分区（1440×1920）

```
y    0 ..  150   顶栏 HUD      系列徽章（左） / 仓库名 + ★（右）
y  158 ..  202   进度轨        4 段（开场 / 定位 / 能力 / 上手）
y  240 .. 1520   舞台 Stage    1224×1280，一块一屏（左右各留 108）
y 1552 .. 1788   字幕带        独占 236px，深色胶囊，两行容量
y 1822 .. 1882   底栏          品牌 + 项目地址
```

**字幕带独占**是本架构最重要的结构改动：旧版字幕无处可放，只能压在内容上，
由此引出字号、折行、页脚让位一整套坑。现在字幕有 236px 专属高度、两行容量，
**折行不再致命**（详见 `pitfalls.md` P16）。

## 二、四条排版规矩（都是抓帧抓出来的）

### 1. 打底帧 ≠ 内容

卡片、格子、选项框的「框」在块起始 **0.3s 内就位**；里面的文字、数字、强调色
才随关键词点亮。

反面教材是 c2 —— 右卡等到口播念到「克隆声音」才从屏幕外飞进来，
于是前半块画面只有左卡、右半屏全空（占位探针实测 35% 时刻右侧 0 列有内容）。

### 2. 禁「★ 0」独立亮相

数字要到 `+4.29s` 才念到，一个 248px 的灰色「0」挂 4 秒多，观众只会当成 bug。

占位要么是**虚线骨架块**（c3 数字位），要么是**灰调实体**（s4 关注条 `opacity:.28`），
念到关键词才转成真内容。灰调占位必须用 `gsap.set`，不能用 `gsap.from`（见 `pitfalls.md` P13）。

### 3. 撑满型板块要封顶，纵向不足的改横排

`flex:1` 会一直撑到舞台底，元素少时卡片变成 **600×1200 的瘦长条**，中间一大片空白；
同一块内容在 3 列并排下是 **392 宽 × 1200 高**（最难看），改 3 行横排就占满舞台中部。

### 4. 不要用 `margin:auto` 撑开两块内容

富余空间会**全部挤到两块之间** —— c3 实测在项目条与星数之间留了 **366px 的整片空洞**
（占位图 3~5 行全空）。要分开就写固定 `margin-top`。

## 三、块内只有两个节拍层

一屏的动画不需要复杂编排，只需要把元素分成两层：

| 层 | 时刻 | 做什么 | 谁负责 |
|---|---|---|---|
| **打底帧** | 块起始 + 0 ~ 0.3s | 框、栏头、网格、终端窗、选项框全部就位 | `@@S@@` 起的补间 |
| **关键词点亮** | `@@W:关键词@@` | 文字 / 数字 / 强调色随声音点亮 | `mark(sel, t)` 加 `.on` 类 |

### 两条判据

**判据一（开头）**：把块起始那一帧单独截出来，应该已经能看出「这一屏要讲什么结构」。
如果截出来只有半屏（或者只有个孤零零的框 / 数字），就是打底帧没做够。

**判据二（结尾）**：把切屏前 0.2s 那一帧截出来，应该是这一屏的「完成态」。
数字滚完了、进度条走满了、该亮的都亮了。如果还在动，说明动画排得比旁白长 ——
`build_video.py` 的 `[动画]` 报表会把这个算成「余量为负」（见 `pitfalls.md` P12）。

**排动画时先算剩余时间，再定时长**：从关键词被念到的时刻到块末，就是这条动画的时间预算。

## 四、时间令牌

每屏的 `html` / `js` 里会出现三类令牌，由 `build_video.py` 解析：

| 令牌 | 含义 |
|---|---|
| `@@S@@` | 该块旁白的起始时刻 |
| `@@W:关键词@@` | 该关键词被念到的时刻（从块内字级时间戳里查） |
| `@@W:关键词\|0.42@@` | 同上；查不到时退回「块起始 + 42% 块时长」 |

第三方件：`@@REPO@@` `@@MEGA@@` `@@STARS@@` `@@WAVE@@` `@@WAVEB@@` `@@CMDCH@@` 等
（由 `video_boards.fill()` 从 `content.json` / `project.json` 填）。

`mark(sel, t)` 由 `build_video.py` 注入到时间轴前导，到 t 时刻给元素**加 `on` 类**，
颜色由 `board_css.py` 里的 `transition` 平滑过渡 —— 这是「念到哪一项哪一项亮」的统一入口。
用类切换而不是直接 tween 颜色，是因为颜色值分散在多条 CSS 规则里（含后代选择器）。

⚠️ 令牌解析是**硬校验**：生成的 JS 里只要还剩 `@@...@@`，`build_video.py`
直接 `SystemExit` —— 因为残留令牌会让整条时间轴语法错误、静默失效。

## 六、占位探针 `check_fill.py`

```bash
"$PY" scripts/check_fill.py                   # 默认全部屏，各在 35% / 85% 两个时刻出图
"$PY" scripts/check_fill.py --blocks=c2,s5    # 只看指定块
"$PY" scripts/check_fill.py --at=0.35,0.85    # 改块内相对时刻
```

它把舞台 1224×1280 投到 **12×16 网格**，输出：

```
c2  t=+2.11s (85%)   占位 87.5%   左 52% / 右 48%
┌──────────────────────────┐
│ #### #### #### #### #### │
│ ...                      │
└──────────────────────────┘
```

### 判读口径

| 指标 | 阈值 | 含义 |
|---|---|---|
| 占位率 | **≥ 45%** | 低于此值基本可以判定「半屏空」 |
| 左占比 | **50% ±15** | 偏离说明画面重心偏在一侧 |
| ASCII 图 | 目视 | 找连续整行的空行（`margin:auto` 撑出的空洞形态就是几整行空） |

**整屏底色屏要单独看**。满屏色块（s3 的克莱因蓝 `.veil`）必须标 `data-deco` ——
它是装饰层，不进占位统计。但这样一来「纯色打底 + 少量文字」的屏会被误报成半屏空
（s3 实测只报 12.5%）。所以脚本会检出**覆盖 ≥70% 且带背景的 `data-deco` 元素**，
给该屏打上 `[整屏底色，占位率不可比]` 并把**它排除在低占位告警之外**。

⚠️ 检出条件必须**同时认 `backgroundColor` 与 `backgroundImage`**：
s3 的 veil 用的是 `linear-gradient()`，此时 `backgroundColor` 是 `rgba(0,0,0,0)`，
只看背景色会让这条保护静默失效（踩过）。

**新增满屏色块时，记得加 `data-deco`**，否则它会被算成内容，把整屏占位率推高、
掩盖真正的空洞。

另一类需要人工判读的是**大字号稀疏元素**（如 c3 的星数）：占位率天然偏低（52%），
要看 ASCII 图确认是「大字留白」而不是「中间挖空」。

## 八、修「抢跑」不能掏空开场（实测踩出来的权衡）

主标题里写着 star 数据，与后面某块口播重叠，按"一块只讲一件事"的原则应该移走。
**但移完之后开场只剩顶部三行小字，下半屏空 3.5 秒，开场直接垮掉** —— 抓帧才看得出来。

修正后的判断标准：

- **标题级元素（封面大字、项目名）属「开场揭晓」，留在开场**，即使它的内容与后面某块重叠。
  观众不会因为标题里先出现过数字就觉得后面的展开无意义；反过来，开场没有视觉落点，
  完播率才是真受损。
- 重叠的数据感由**动作**补回来：让星数卡用 `back.out(1.6)` 弹出 + 数字从 0 滚到 29.8k，
  与静态标题形成"呼应"而不是"重复"。
- 一句话：**先看开场有没有垮，再看有没有抢跑。**
